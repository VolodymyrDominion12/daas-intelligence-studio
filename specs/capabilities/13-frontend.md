## 1. Призначення
Одна сторінка-студія українською: список задач, створення задачі, робочий простір із вкладками,
живий журнал подій. UI — тонкий клієнт над API (11); бізнес-правила живуть у backend.

## 2. Структура

| Компонент | Відповідальність |
|:---|:---|
| `App` | конфіг, список задач, вибрана задача, polling кожні 2.6 с, SSE-журнал, toast-и |
| `Sidebar` | список задач, статуси, кнопка «Нова задача» |
| `NewTask` | промпт + 1–3 seed-URL + назва |
| `TaskWorkspace` | дії (Калібрувати / Зібрати / Збагатити / Снапшот / Скасувати), вкладки: План, Дані, Калібрування, Зміни, Дублікати, Експорт, Джерела |
| `PlanPanel` | колонки (додати/видалити, AI-колонка), ліміти, якість |

## 3. Вимоги

### REQ-UI-001 — Токен і API-клієнт
Клієнт **ПОВИНЕН** брати токен з `<meta name="daas-token">` (вбудовується backend-ом) або з
`__DAAS_TOKEN__` (Vite dev читає `storage/runtime.json`), надсилати `Authorization: Bearer` і
додавати `?token=` лише для SSE/завантажень. Помилка API → `ApiError(status, detail)` з текстом
`detail` від сервера.
- **Перевірка:** — (прогалина; компіляція — `npm run build`)

### REQ-UI-002 — Контракт типів синхронний з backend
`frontend/src/types.ts` і `api.ts` **ПОВИННІ** відповідати моделям і ендпоінтам backend
(00, 11). Зміна API без зміни типів у тому самому PR заборонена.
- **Перевірка:** `npm run build` (лише TS-компіляція; контрактних тестів немає — прогалина)

### REQ-UI-003 — Підтвердження high-risk джерела
На відповідь 428 від `calibrate`/`run` UI **ПОВИНЕН** показати повідомлення сервера, запитати
причину і повторити запит один раз з `acknowledge_high_risk=true` і `reason`; порожня причина —
скасування.
- **Перевірка:** — (прогалина)

### REQ-UI-004 — Живий журнал
UI **ПОВИНЕН** завантажити історію подій (`/events`, ≤ 500), потім підписатися на SSE і зливати
події без дублікатів за `id`; без SSE — працює polling.
- **Перевірка:** — (прогалина)

### REQ-UI-005 — Стани порожньо / завантаження / помилка
Кожна панель з даними **ПОВИННА** мати стан завантаження, порожній стан із підказкою наступного кроку
і показ помилки (toast). Без зібраного UI backend віддає сторінку-підказку (REQ-API-007).
- **Перевірка:** — (прогалина; візуальні регресійні тести відсутні — `docs/03` §7 п.14)

### REQ-UI-006 — Мова
Увесь текст інтерфейсу — **українською** (перемикача мов немає).
- **Перевірка:** рев'ю

## 4. Прогалини
Автотестів UI немає зовсім. Кандидати: Vitest для `api.ts`/`format.tsx`, Playwright smoke проти
`daas demo --serve` (Chromium уже доступний у середовищах агентів).
