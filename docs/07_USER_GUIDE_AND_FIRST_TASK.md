# Посібник користувача: робота з інтерфейсом і перша задача після деплою на VPS

> **Для кого цей документ:** для власника студії, який щойно підняв DaaS Intelligence Studio на
> VPS (або локально), бачить стартовий екран і хоче швидко зрозуміти, як працює кожна вкладка
> інтерфейсу, яку першу задачу запустити прямо зараз і що налаштувати далі.

---

## 1. Що перевірити одразу після деплою на VPS

### 1.1. Бейджі стану внизу стартового екрана

У нижній частині екрана студія показує активні можливості вашого інстансу:

| Бейдж | Що означає | Чи заважає старту? |
|:---|:---|:---|
| `LLM офлайн · локальні шаблони` | Локальний (Ollama) або хмарний LLM не підключений | **Ні.** Шаблони схем, Prozorro API, JSON-LD, CSS-калібрування і аудит сайтів працюють без LLM (`$0` витрат). |
| `robots.txt: так` | Студія поважає `robots.txt` та `Crawl-delay` | **Так і має бути** (комплаєнс). |
| `2 збагачувачів` | Активні вбудовані модулі `site_audit` (email, телефони, соцмережі, техстек, онлайн-запис) і `domain_resolver` (пошук сайту компанії) | Готово до роботи. Для пошуку невідомих сайтів через `domain_resolver` опційно підключається SearXNG (`DAAS_SEARXNG_URL`). |
| `fetch: http` | Стандартний швидкий HTTP-клієнт (`httpx`) | **Ідеально для Open Data API та статичних/SSR сайтів.** Для SPA-сайтів із порожнім JS-DOM пізніше можна додати Playwright-сайдкар (`--profile playwright`). |

### 1.2. Обов'язковий мінімум безпеки для публічного VPS

> **Важливо:** за замовчуванням студія створювалась як local-first інструмент і вбудовує свій
> `DAAS_API_TOKEN` у HTML-сторінку під час віддачі. Якщо ваш VPS дивиться в інтернет (наприклад,
> через `*.sslip.io` або власний домен), **обов'язково закрийте доступ на рівні reverse proxy**
> (Caddy `basic_auth`, Cloudflare Access або Tailscale/WireGuard VPN), щоб сторонні не могли
> відкривати інтерфейс і запускати задачі.

Приклад `basic_auth` у `/etc/caddy/Caddyfile` (хеш генерується командою `caddy hash-password`):

```caddyfile
daas.your-domain.com {
	encode gzip

	basic_auth {
		admin $2a$14$...хеш_пароля...
	}

	reverse_proxy 127.0.0.1:8000 {
		flush_interval -1
	}
}
```

Також перевірте в `.env` на VPS:
- `DAAS_CORS_ORIGINS=https://ваш-домен` — щоб DNS-rebinding guard пропускав ваш домен;
- `DAAS_API_TOKEN=<довгий-випадковий-секрет>` — стабільний токен для скриптів і бекапів;
- щоденний бекап через `deploy/scripts/backup-and-upload.sh` (деталі — у [`deploy/README.md`](../deploy/README.md)).

## 2. Огляд інтерфейсу

Інтерфейс складається з трьох зон: **лівої навігаційної панелі**, **центрального робочого простору**
та **правої колонки «Живий журнал»** (з'являється після вибору задачі).

### 2.1. Ліва панель (Sidebar)

- **`+ Нова задача`** — відкриває майстер створення задачі.
- **Список задач (`ЗАДАЧІ`)** — показує назву, статус (`draft`, `calibrated`, `running`, `ready`,
  `failed`), кількість записів у поточному датасеті та час останнього оновлення.
- **Футер панелі** — загальні витрати `$ LLM`, кількість сторінок у raw-кеші (`кеш`), кількість
  завдань `у черзі`, статус LLM і `fetch`-рушія, а також шлях до `storage`.

### 2.2. Вікно «Нова задача»

1. **Бізнес-питання природною мовою** — опишіть, які сутності й поля потрібні. Якщо LLM не
   підключений, студія автоматично підбере один із вбудованих офлайн-шаблонів (Prozorro Переможці,
   Prozorro API, Prozorro.Продажі, локальний бізнес, B2B-компанії, нерухомість, e-commerce,
   вакансії, тендери).
2. **Кнопки-приклади** — швидке заповнення промпту, назви та (для Prozorro) стартового URL в один
   клік.
3. **Стартові URL** — по одному в рядку: сторінка каталогу/рубрики, список об'єктів або endpoint
   відкритого JSON API. URL із логінами/паролями чи токенами сесії автоматично відхиляються
   (тільки публічні logged-out сторінки).
4. **Назва задачі** — необов'язкова; якщо не вказати, згенерується з промпту.
5. **Секція «Налаштувати відкритий JSON API (`api_source`)»** — розгортається лише тоді, коли ви
   підключаєте *власний* JSON API (наприклад, TED Europa, SAM.gov, відкриті реєстри), для якого
   потрібно вручну задати `items_path`, `id_path`, курсор пагінації та `field_map`. Для Prozorro
   та Prozorro.Продажі ця секція **не потрібна** — їхній профіль підхоплюється автоматично.

### 2.3. Верхня панель задачі та 4 кнопки пайплайну

```text
Нова задача ──▶ [Калібрувати]* ──▶ [Зібрати] ──▶ [Збагатити] ──▶ [Снапшот] ──▶ Експорт / Доставка
```

- **Калібрувати** — завантажує 2–4 тестові сторінки, визначає стратегію (`JSON-LD` / `CSS-селектори`
  / `LLM`) і показує прев'ю витягнутих рядків.
  - *Для HTML-сайтів:* **обов'язковий крок перед «Зібрати»** (інакше студія зупинить запуск із
    підказкою).
  - *Для Open Data JSON API (Prozorro / Prozorro.Продажі):* **можна пропустити** — мапінг JSON
    уже заданий декларативно, тому після створення задачі можна одразу тиснути **«Зібрати»**.
- **Зібрати** — запускає фоновий збір у стійкій черзі SQLite (із повагою до `robots.txt`,
  rate-limit, кешуванням сирих сторінок і дедуплікацією).
- **Збагатити** — запускає налаштовані збагачувачі поверх уже зібраних рядків (`domain_resolver`,
  `site_audit` для пошуку email/телефонів/соцмереж/техстеку та AI-колонки, якщо є LLM).
- **Снапшот** — фіксує нову версію датасету у Parquet, порівнює її з попередньою та генерує події
  змін (`new_entity`, `field_changed`, `price_drop`, `removed_entity`), які запускають підписки
  доставки (Telegram / Webhook).
- **Зупинити** — з'являється під час активного прогону й акуратно скасовує поточний запуск.

Під заголовком відображається **смужка метрик**: `Сторінок`, `Нових (+N)`, `Оновлено (↻N)`,
`Зникло (−N)`, `Карантин`, витрати `LLM ($)`, підсумок останнього запуску та бейджі якості даних.

### 2.4. Усі 9 вкладок робочого простору

| Вкладка | Призначення | Коли використовувати |
|:---|:---|:---|
| **План** | Схема колонок (додавання, редагування, порядок, видалення, типи, PII-мітки, власні CSS-селектори, промпти для AI-колонок), стартові URL, ліміти (`max_pages`, `max_depth`, `budget_usd`, `sample_size`), збагачувачі та **тригер авто-збагачення** (`auto_enrich`). | Одразу після створення задачі — щоб зменшити/збільшити `max_pages`, підправити колонки або налаштувати поріг суми для `auto_enrich`. |
| **Дані** | Інтерактивна таблиця записів із серверним пошуком, фільтром по конкретній колонці, сортуванням кліком по заголовку, пагінацією по 50 рядків і бейджем впевненості `Conf %`. **Клік на будь-який рядок** відкриває бокову панель **«Походження запису»**: метод екстракції кожного поля, впевненість, посилання на джерело та повну append-only історію версій (`v1`, `v2`…). | Після «Зібрати» та «Збагатити» — перевірити якість даних і окремі записи. |
| **Калібрування** | Звіт тестового прогону для HTML-сайтів: обрана стратегія, % заповненості кожної колонки, прев'ю записів, **Schema Diff** між версіями калібрування та кнопка **«Відкотити схему»**. | Перед першим «Зібрати» на HTML-сайті або коли сайт змінив верстку. |
| **Розклад і доставка** | 1) **Cron-розклад** автозбору (пресети: кожні 15 хв, щогодини, щодня 06:00 UTC, щотижня; опція `catch_up`). 2) **Підписки доставки** у **Telegram** або **Webhook** із фільтрами (`event_types`, ключові слова, стоп-слова, CPV-префікси, регіони, мін/макс сума, `field_filters`, режим `instant` або дайджест). 3) **Якість і Gold-set Eval**. | Коли задача стабільно збирає дані вручну і ви хочете перевести її в автоматичний режим. |
| **Зміни** | Історія дельт між снапшотами: нові записи (`new_entity`), зміна полів (`field_changed`), падіння ціни (`price_drop`), зниклі об'єкти (`removed_entity`). | Після 2-го і наступних прогонів + «Снапшот». |
| **Карантин** | Підозрілі або неповні записи, відфільтровані правилами якості. Кожен запис можна **«Підтвердити»** (перенести в основний датасет) або **«Відхилити»**. | Коли на вкладці з'являється лічильник `> 0`. |
| **Дублікати** | Кандидати на дублікати всередині датасету з можливістю переглянути поля, об'єднати (**Merge**) або роз'єднати (**Unmerge**). | Перед експортом клієнту або після збору з кількох джерел. |
| **Експорт** | Вивантаження датасету у **Excel (`.xlsx` із форматуванням і аркушем маніфесту)**, **CSV (UTF-8 BOM)**, **Parquet** або **JSON**. Перемикач маскування PII (`business_contact` можна відкрити; `personal` маскується завжди), ліміт рядків і список останніх файлів. | Коли потрібно передати дата-продукт клієнту або відкрити в Excel/BI. |
| **Джерела** | Реєстр комплаєнсу по доменах: рівень ризику `tos_risk` (`low`, `medium`, `high`, `forbidden`), ліцензія, нотатки. `forbidden` жорстко блокує запуск; `high` запитає причину для журналу аудиту. | Перед регулярним збором із нового домену — зафіксувати його політику та ліцензію. |

### 2.5. Права панель «Живий журнал»

Відображає потік подій (SSE) у реальному часі: які сторінки завантажуються, скільки записів
додано/оновлено, попередження `robots.txt` чи мережеві помилки. Є перемикач **`всі / важливі`**
(лише попередження й помилки) та кнопка **`пауза`**.

## 3. Яку першу задачу зробити прямо зараз

Нижче — 3 перевірені сценарії, від найпростішого (працює на вашому VPS за 5 хвилин без жодних
додаткових ключів) до комерційного B2B-продукту та HTML-парсингу.

### Варіант 1 (Рекомендований старт за 5 хвилин): Prozorro API або Prozorro.Продажі

**Чому саме це першим:**
- Працює на поточній конфігурації VPS **прямо зараз** (`LLM офлайн`, `fetch: http`, `$0` витрат).
- Офіційний відкритий JSON API (`public.api.openprocurement.org`) — нуль Cloudflare, капч і проксі.
- Вбудована кнопка-приклад у вікні «Нова задача» і повний цикл: збір → інкрементальне оновлення →
  снапшот → детекція змін → експорт XLSX з маніфестом.

**Покроково:**

1. Натисніть **«Створити першу задачу»** (або **`+ Нова задача`** зліва).
2. Натисніть кнопку-приклад **«Prozorro API (тендери)»** або **«Prozorro.Продажі API»**.
   - Промпт, стартовий URL (`https://public.api.openprocurement.org/api/2.5/tenders` або
     `https://public.api.openprocurement.org/api/0/auctions`) і назва заповняться автоматично.
3. Натисніть **«Створити задачу»**.
4. У вкладці **«План»** прокрутіть до блоку **«Ліміти»**:
   - Для першого тестового прогону поставте **`Макс. сторінок (max_pages) = 10`** (за замовчуванням
     `50`; 10 сторінок зберуться швидше і дадуть першу вибірку тендерів/аукціонів із деталями).
   - Натисніть зберегти ліміти.
5. Натисніть кнопку **«Зібрати»** у верхній панелі (калібрувати для `api_json` не потрібно).
   - Слідкуйте за прогресом у **«Живому журналі»** праворуч і в смужці метрик зверху.
6. Після завершення перейдіть у вкладку **«Дані»**:
   - Спробуйте пошук, фільтр по колонці (наприклад, `region` або `status`) і сортування по `amount`.
   - Клікніть по будь-якому рядку — відкриється панель **«Походження запису»** з прямим посиланням
     на тендер/лот у Prozorro.
7. Натисніть **«Снапшот»** — створиться версія `v1` у Parquet.
8. Зачекайте 5–10 хвилин і натисніть **«Зібрати»** ще раз (студія використає збережений
   інкрементальний курсор і підтягне лише нові зміни), а потім знову **«Снапшот»**.
   - Відкрийте вкладку **«Зміни»** — ви побачите реальну дельту (`new_entity`, `field_changed`,
     `price_drop`).
9. Перейдіть у вкладку **«Експорт»** → оберіть **Excel** → **«Створити експорт»** → завантажте
   `.xlsx` і подивіться як дані, так і аркуш маніфесту.

### Варіант 2 (Перший комерційний B2B-продукт): «Prozorro Переможці (B2B)» + авто-аудит сайтів

Коли переконаєтесь, що базовий цикл працює, створіть задачу на базі комерційного тригера з
[`docs/05_FIRST_PRODUCT_LAUNCH_PLAN.md`](./05_FIRST_PRODUCT_LAUNCH_PLAN.md):

1. **`+ Нова задача`** → клікніть кнопку-приклад **«Prozorro Переможці (B2B)»** → **«Створити задачу»**.
2. У вкладці **«План»** зверніть увагу на вже налаштовані елементи:
   - Колонки переможця (`winner_name`, `winner_edrpou`, `award_amount`, `award_status`, `award_date`)
     + колонки збагачення (`website`, `email`, `phone`, `socials`, `tech_stack`).
   - Збагачувачі: `domain_resolver` + `site_audit`.
   - **Тригер авто-збагачення (`auto_enrich`)**: увімкнений для активних перемог із сумою від
     `1 000 000` грн (можете змінити поріг під свою нішу, наприклад `500 000` грн).
3. Натисніть **«Зібрати»**, а далі (або автоматично через `auto_enrich`) — **«Збагатити»**.
   - *Примітка:* `site_audit` перевірить сайти переможців, де URL є в даних Prozorro, і витягне
     бізнес-email, телефони, соцмережі та техстек сайту. Якщо додатково підключити SearXNG
     (`DAAS_SEARXNG_URL`), `domain_resolver` також автоматично шукатиме офіційний сайт за назвою
     компанії та регіоном.
4. Перейдіть у вкладку **«Розклад і доставка»**:
   - Увімкніть розклад, наприклад **`Щогодини` (`0 * * * *`)** або **`Кожні 15 хв` (`*/15 * * * *`)**.
   - Додайте **Telegram-підписку** (потрібен `DAAS_TELEGRAM_BOT_TOKEN` у `.env` на VPS): вкажіть
     свій Chat ID або `@channel`, оберіть `new_entity`, задайте потрібні **CPV-префікси** (наприклад,
     `45` — будівництво, `72` — ІТ-послуги, `33` — медтехніка), регіон і мінімальну суму.

Після цього ваш VPS працює як автономний **Alerts-as-a-Service** і постачає готові B2B-ліди
прямо в Telegram або Webhook (n8n / Make / CRM).

### Варіант 3 (Перевірити HTML-парсинг і CSS-калібрування)

Якщо хочете протестувати саме двофазний HTML-парсер (калібрування → CSS-схема → збір):

1. Оберіть простий статичний каталог без Cloudflare і важкого SPA — для безпечного першого тесту
   чудово підходить навчальний каталог `https://books.toscrape.com/` (або будь-який публічний
   HTML-каталог із `robots.txt`, що дозволяє краул).
2. **`+ Нова задача`**:
   - Промпт: `Збери каталог книг: назва, ціна, наявність, рейтинг, посилання`
   - Стартовий URL: `https://books.toscrape.com/`
3. У вкладці **«План»** поставте `max_pages = 5`, `max_depth = 1`.
4. Натисніть **«Калібрувати»** — студія автоматично відкриє вкладку **«Калібрування»** і покаже:
   - знайдену стратегію (`CSS-селектори` або `JSON-LD`);
   - відсоток заповненості кожного поля;
   - прев'ю перших рядків.
5. Якщо якесь поле не знайшлося — у вкладці **«План»** клікніть редагувати колонку, вкажіть точний
   CSS-селектор і натисніть **«Перекалібрувати»** (у **Schema Diff** одразу буде видно різницю
   покриття, а за невдачі можна натиснути **«Відкотити схему»**).
6. Коли прев'ю влаштовує — натисніть **«Зібрати»** → **«Снапшот»** → **«Експорт»**.

## 4. Що робити далі на VPS (покроковий план розвитку)

1. **Закрийте доступ до UI** (Caddy `basic_auth` або VPN) — див. §1.2.
2. **Налаштуйте Telegram-алерти** для себе:
   - Створіть бота через `@BotFather`, додайте `DAAS_TELEGRAM_BOT_TOKEN=...` у `.env` і перезапустіть
     контейнер (`docker compose -f docker-compose.prod.yml up -d`).
   - У вкладці **«Розклад і доставка»** прив'яжіть підписку на свій Telegram Chat ID і ввімкніть
     галочку сповіщень про помилки, щоб знати, якщо джерело впаде або поверне 0 записів.
3. **Увімкніть щоденні бекапи** у `cron` на VPS (`deploy/scripts/backup-and-upload.sh`, інструкція —
   у [`deploy/README.md`](../deploy/README.md)).
4. **Додавайте опційні модулі лише тоді, коли вони реально знадобляться:**
   - **LLM** (`DAAS_LLM_BASE_URL` + `DAAS_LLM_API_KEY` + `DAAS_LLM_MODEL`, наприклад `gpt-4o-mini`
     або локальний Ollama) — коли захочете AI-колонки (скоринг лідів, витягування болю з описів)
     або LLM-генерацію плану з довільного промпту.
   - **SearXNG** (`DAAS_SEARXNG_URL`) — коли захочете автоматично знаходити сайти компаній у
     `domain_resolver` (наприклад, для переможців Prozorro без вказаного URL).
   - **Playwright-сайдкар** (`docker compose -f docker-compose.prod.yml --profile playwright up -d` +
     `DAAS_FETCH_ENGINE=auto` + `DAAS_PLAYWRIGHT_SIDECAR_URL=http://playwright-sidecar:8765`) —
     коли почнете парсити JS/SPA-сайти, які без браузера віддають порожній HTML.
5. **Запускайте перший платний продукт:** покроковий Go-to-Market план (вибір вузької підніші,
   тарифи, тонкий Telegram-бот підписників і монетизація) описано в
   [`docs/05_FIRST_PRODUCT_LAUNCH_PLAN.md`](./05_FIRST_PRODUCT_LAUNCH_PLAN.md) та
   [`docs/06_DEVELOPMENT_AND_MONETIZATION_PLAN.md`](./06_DEVELOPMENT_AND_MONETIZATION_PLAN.md).

## 5. Часті питання та типові помилки

- **«Натискаю "Зібрати", а студія каже: спершу запустіть калібрування»**
  Для HTML-сайтів це захист від марного краулу й витрат на LLM: спершу натисніть **«Калібрувати»**,
  перевірте прев'ю, потім **«Зібрати»**. Для `api_json` задач (Prozorro) калібрування не вимагається.
- **«Калібрування HTML-сайту дало 0 записів»**
  Перевірте **Живий журнал** і попередження у вкладці **«Калібрування»**. Найчастіші причини:
  1) сайт рендериться через JavaScript (потрібен Playwright-сайдкар і `DAAS_FETCH_ENGINE=auto`);
  2) `robots.txt` забороняє краул;
  3) спрацював WAF/Cloudflare (`blocked`).
- **«З'явилось вікно з питанням про причину запуску (HTTP 428)»**
  Домен позначений у вкладці **«Джерела»** як `high` risk. Введіть обґрунтування — воно збережеться
  в аудит-лозі запуску. Домени зі статусом `forbidden` не запускаються взагалі.
- **«Чому в експорті замасковані email / телефони?»**
  У вкладці **«Експорт»** за замовчуванням увімкнена опція «Маскувати PII». Для колонок класу
  `business_contact` її можна зняти, якщо це дозволено вашим сценарієм. Колонки класу `personal`
  маскуються завжди і не експортуються відкрито.
- **«Чи можна запускати CLI-команди `daas collect / backup` на VPS, поки працює Docker-контейнер?»**
  **Ні** для команд, що пишуть у DuckDB (один процес-writer на сховище). Під час роботи сервера
  використовуйте UI або HTTP API (зокрема `POST /api/maintenance/backup` для бекапу наживо — скрипт
  `deploy/scripts/backup-and-upload.sh` робить це автоматично).
